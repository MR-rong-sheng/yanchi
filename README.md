# 砚池 · 语文学习工具 v2.0

一个安静的语文学习工具骨架，内容覆盖**统编版九年级上册（2024 审定版 / 2026 秋启用）**。
界面用液态玻璃做成，内容与界面分离——**改内容不用改代码，加模块只要写一个文件**。
v2.0 起带账号：整站需要登录，管理员另有一个后台（概览 / 账号 / 内容 / 曲库 / 记录）。

打开方式：双击 `启动服务.bat`，或在本目录执行

```bash
python -u serve.py 8081 .
```

然后访问 <http://127.0.0.1:8081/>。**第一次打开会让你创建管理员账号**（用户名 + 密码，密码至少 6 位），
之后每次访问都要登录；登录页上有「忘记密码」的处理办法见文末。

⚠ 不要再用 `python -m http.server` 起这个站：它没有 Range、不认账号，等于把门开着。

## 账号与后台

**第一次打开**站点会引导你创建管理员账号（用户名 2–24 字，密码至少 6 位）——这一步只在
一个账号都没有时可用；建好之后 `/api/setup` 就永久关掉了。

- **登录**：整站（含音频与 content/\*.json）都需要登录；只有 `login.html` 和它引用的
  `auth.css`、`glass.css`、`login.js` 是免登录的。
- **登录会怎么失效**：Cookie 是**会话级**的（关掉浏览器即失效）；服务端另有
  **12 小时闲置过期**（超过 12 小时没有任何请求就要重新登录）和 30 天上限。
- 任何页面未登录访问都会跳到登录页（含 `/index.html`）；只有接口类请求才回 401 JSON。
- **顶栏右上角「账号」按钮** → 账号抽屉：看自己是谁、改密码、退出登录；管理员多一项
  「后台管理」。改密码会让所有设备上的会话立刻失效，需要重新登录。
- **后台管理**（`#/admin`，仅管理员可见）五个标签页：
  - **概览**：曲库首数与占用、账号数、在线会话、C/D 盘剩余、服务版本与运行时长、最近登录；
  - **账号**：新建（含管理员）、改密、改角色、停用/启用、删除；服务端守着
    「最后一个管理员不能降级/停用/删除」「不能删自己」；
  - **内容**：直接在网页里编辑 `units/words/poems/prompts` 四份 JSON，本地校验 → 保存；
    每次保存前自动备份到 `.private/backup/`（每份留最近 10 个），可一键还原；
  - **曲库**：搜索、分页、把某首**移入回收站**（`D:\yanchi-trash`，可放回）、
    以及「重建清单」（等于跑一遍 `tools/build-library.py`，把 `D:\CloudMusic` 里的新歌补进来）；
  - **记录**：操作日志（登录、改动、后台动作都记）与在线会话，可把某个会话踢下线。
- **忘了密码 / 账号全没了**：命令行解决——
  `python serve.py users` 看账号，`python serve.py passwd <用户名>` 改密，
  `python serve.py adduser <用户名> --admin` 补一个管理员；
  实在都进不去，删掉 `.private/yanchi.db`（会一并丢掉会话与操作记录），下次打开重新初始化。
- **命令行清单**：`users` ｜ `adduser <名> [--admin]` ｜ `passwd <名>` ｜ `deluser <名>` ｜
  `kick`（清掉所有会话）｜ `dev on|off`（自检用的临时直通，**默认关，验完必须关**）。
- **数据在哪**：全部在 `.private/`（`yanchi.db` + `backup/`）。这个目录对 HTTP 一律 404，
  因为它以 `.` 开头；连同 `serve.py`、`tools/`、`*.bat`、`README.md` 都在拒绝名单里。
- **想从别的脚本调后台**：接口契约见 `tools/API.md`，写操作要带 `X-Requested-With: yanchi-fetch` 头。

安全上做了什么（都在 `serve.py`）：口令用 PBKDF2-SHA256 加盐哈希；会话是服务端的，
Cookie 里只有随机令牌、库里存的是它的 SHA-256；HttpOnly + SameSite=Lax；
写操作校验自定义头与 Origin（CSRF）；登录失败限速；路径穿越与敏感路径拒绝；
音频 Range 支持保留。

### 自助注册（登录页的「创建账号」）

- 登录页上的「创建账号」按钮由服务端开关控制：`/api/me` 返回 `register:true` 才显示。
- 开关在 **后台 →「账号」标签**；关掉之后 `/api/register` 直接 403，按钮也会消失。
- 自助注册的账号角色**固定为 `user`**（能看前台，进不了后台）；同一个 IP 10 分钟内最多注册 5 次。
- ⚠ 公网地址是公开的：开着这个开关，任何拿到链接的人都能自己建号看你的站。只想自己用就关掉。

### 操作存档（每个账号一份）

- 位置：`.private/archive/<账号>.jsonl`，**JSON Lines**，一行一条；单份超过 4 MB 轮转成 `<账号>.1.jsonl`。
- 字段固定：`t`(Unix 秒) `ts`(可读时间) `u`(账号) `ev`(事件码) `d`(详情) `ip` `ua`。
- **记什么**：服务端动作（登录/退出/改账号/改内容/曲库增删/改设置…）与前端轨迹
  （`boot` 打开站点、`view` 进了哪页+停留多久、`click` 点了什么、`prefs` 改了偏好；
  视图里还能用 `ctx.track('note', '新增札记 …')` 自己补事件）都写进同一个文件，
  按 `t` 排序就是这个人在站内的完整轨迹。
- **怎么看**：后台 →「记录」标签的「操作存档」区（看最近 N 条 / 下载 JSONL）；
  或双击项目里的 **`看存档.bat`**（列出所有存档，再挑一个看最近 40 条）；
  或命令行 `python serve.py archive`（列出所有存档）、`python serve.py archive rongsheng 50`（看某人的最近 50 条）。
- 事件码与格式的完整定义在 `tools/API.md`。


## 怎么改

**换内容**（不用碰代码）：编辑 `content/*.json`。四个文件的字段如下——

- `units.json`：
  `{id, 序号, 主题, 副题, 导语, 课文:[{no, 题, 作者, 体裁, 精读, 导读, 要点[]}],
    写作:{题, 要点[]}, 其他:[{类型, 题, 说明}]}`
  课文点开后，会按题名自动去诗文库里找可读的原文并给出跳转按钮。
- `words.json`：`id, 字, 音, 义, 标签[]`，另可带 `部首, 笔画, 例, 用`（原创字词札记）
  或 `课, 单元`（课本词表）。两种条目在界面上都能正常显示。
- `poems.json`：`id, 题, 作者, 朝代, 类, 体裁, 单元, 原文[], 注释[{词,释}], 析[], 名句[], 标签[]`
  其中 `类` 决定排版：`诗`/`词`/`曲` 按句居中，`文` 按段左对齐并首行缩进。
- `prompts.json`：`id, 题, 体裁, 材料, 提示[], 结构[], 标签[]`

**加模块**：在 `assets/js/views/` 里新建一个文件，导出

```js
export default {
  id: 'idioms', name: '成语', icon: 'words',
  nav: true,                       // 是否出现在顶栏导航
  async mount(root, ctx) {         // root = #view 容器，ctx = 框架能力
    root.innerHTML = `<div class="card glass spec">…</div>`;
  },
};
```

再到 `assets/js/app.js` 的 `ROUTES` 里加一行 `import`，导航会自动多出一项。

`mount(root, ctx)` 拿到的 `ctx`：
`go(id)` 跳转 · `store` 本地存储 · `toast(msg)` 提示 · `openDrawer/coseDrawer` 抽屉 ·
`prefs` 外观偏好 · `render()` 重绘 · `ic(name)` 图标 · `esc(s)` 转义 ·
`download(name, text, mime)` 下载 · `countHan/countAll` 字数 · `stamp(ts)` 时间格式。

**加图标**：在 `index.html` 的 SVG 精灵里加一个 `<symbol id="i-xxx" viewBox="0 0 24 24">`，
线稿风格：`fill:none; stroke:currentColor; stroke-width:1.6; stroke-linecap:round`。

## 播放器

**放你自己导入的音频**——朗读、吟诵、读书时听的曲子都行。设计上守三条：

- **不联网、不带任何第三方音频**。文件通过「选择音频 / 拖放」导入，存进浏览器 IndexedDB，
  只在这台电脑上；清空或移除即从本机删除。站点自带的只有一首 `assets/audio/demo.wav`
  （用五声音阶合成的 4 秒示例，供一键试听，确认你的设备能不能出声）。
- **支持**：列表播放、切上一首/下一首、点击或拖动进度条、音量、三种模式（列表循环 / 单曲循环 / 随机）、
  空格播放暂停、← → 快退快进 5 秒、系统级媒体控制（锁屏/耳机按键，浏览器支持时）。
- **不打扰阅读**：选过曲子后右下角常驻一枚玻璃胶囊，切到诗文页也能接着放，点胶囊回到播放器。

在无头浏览器里跑自检时，音频播放会让虚拟时间按真实时间推进，`#播放` 组会明显变慢——
这是环境特性，不是页面问题；加 `--mute-audio` 可以缓解。

## 站内曲库

播放页里除了「自己导入」，还有一块**站内曲库**：曲目清单在 `content/music.json`，
音频文件放在站点的 `music/` 目录里，点一首就播，支持搜索歌手/曲名、全部播放、随机播放。

- **不占额外磁盘**：`music/` 是指向实际音乐目录的 junction（`mklink /J`），
  里面的文件用 NTFS 硬链接汇集，同一份数据两个名字，没有复制。
- **清单怎么生成**：扫音乐目录 → 硬链接进库 → 写 `content/music.json`（`file/title/artist/size/ext`）。
  加了新歌重跑一次生成脚本即可。
- **置顶**：想让某几首排在列表最前（例如刚收到的一段音频），把文件名/标题写进
  `content/pinned.json`（JSON 数组，按列出顺序置顶），再跑一次生成脚本即可 —— 不用改代码，
  也不用靠给文件名加前缀去凑字母序。`tools/build-library.py` 会先排置顶项，其余仍按文件名排序。
- **为什么不用 `python -m http.server`**：它不支持 Range 请求，音频只能整首下完才播、**进度条拖不动**，
  而且会把目录列表暴露出去。改用站点自带的 `serve.py`：支持 206 分段（边下边播、可拖动）、
  不列目录（目录无 index.html 一律 404）、多线程 + keep-alive。
  `启动服务.bat` 已经换成 `python serve.py 8081 .`。

### 现在的曲库规模

262 首 / 18.49 GB（248 个 flac + 14 个 mp3）。构成是「源目录里原有的 126 flac + 14 mp3」加
「从 230 个 ncm 里解出来的 122 首」——另外 108 个 ncm 的内容早就有对应文件，直接跳过。

**ncm 是怎么解的**：ncm 只是网易的容器，里面装的是 flac 还是 mp3 因曲而异（这批里有 14 首是 mp3，
其中还有 96kbps 的）。用 PyPI 的 `ncmdump`（清华源装，依赖 pycryptodome）解，**按容器里的原始格式
输出，不把 mp3 硬转成 flac 冒充无损**：

```bash
python -m ncmdump.app -o "D:/CloudMusic/decoded" "<某个.ncm>"   # 单文件
python -u tools/decode-batch.py --decoder 'python -m ncmdump.app -o "{o}" "{i}"' --workers 6
```

`tools/decode-batch.py` 是我写的批处理：多进程、单文件超时、**解完立刻用 ffprobe 验时长和编码**、
断点续跑（已有的合格文件跳过）、结果写 `decode_report.json`。它有个坑要记住：**ncmdump 默认静默跳过
同名已存在文件**，所以补跑前必须先删掉失败留下的 0 字节空文件，否则永远补不上。

### 开机自启

`开机自启.bat` + 启动文件夹里的「砚池.lnk」：登录时自动拉起 `serve.py` 和公网隧道，

## 自检与全站按键巡检

打开 <http://127.0.0.1:8081/_selftest.html>，它会用 iframe 驱动真实页面，跑两类检查：

**一、断言（约 50 条）**：七个视图渲染、检索过滤、抽屉、札记写入、进度写入、草稿自动保存、
偏好切换与持久化、课本与诗文库联动、文言文按段排版、单元筛选，以及"设置页按钮不得污染偏好"的回归用例。
条目数断言直接从 `content/*.json` 读取，因此增删内容不会误报。

**二、按键巡检（第 10 节）**：清空本机数据后，逐个点击界面上每个可交互元素——导航、顶栏、
字卡、课文行、篇目卡、写作题卡、分段器、下拉、抽屉动作、导出/备份/清空——并断言**点击后确实产生了变化**
（跳转、开抽屉、写存储、触发下载或确认框）。没有变化的会被记为"无响应"。
长列表（143 张字卡等）按等距抽样；其余全量。

也可以只跑某一组，便于定位：

```
http://127.0.0.1:8081/_selftest.html#字词     或 #顶栏 #导航 #今日 #课本 #诗文 #写作 #札记 #设置
```

命令行：

```bash
chrome --headless=new --force-prefers-reduced-motion --virtual-time-budget=120000 \
       --dump-dom "http://127.0.0.1:8081/_selftest.html" | sed -n 's/.*<pre id="T">//p'
```

巡检抓到过的真实缺陷（均已修复）：

- `today.js` / `units.js` 里的跨模块跳转用了 `wordsView.openById(...)`，但 `openById` 是具名导出、
  并不在默认导出对象上，点击时抛 TypeError，导致「细看这个字」「读全篇」「去写这一篇」「读原文」
  四个按钮全是死键。修法：把 `openById` 挂到各视图的默认导出上。
- 字词页 143 张卡片各自带 SVG 位移滤镜，每次重绘都要为每个玻璃面重算，整页操作慢到不可用。
  修法：长列表卡片与按钮只保留模糊，折射滤镜只留给大块玻璃面。

## 设计约定

- **一个强调色**：青 / 赭 / 紫 / 墨，全站只用这一个色，其余是墨色阶梯。
- **玻璃只做两件事**：折射背后的画面（`feTurbulence` + `feDisplacementMap`）与分层，
  不做彩色霓虹。悬停时高光跟鼠标走，收敛到 50% 不透明度。
- **数据留在本机**：全部走 `localStorage` 的 `yanchi:` 前缀，无账号、无上传、无埋点。

   《邹忌讽齐王纳谏》第 140 页）以及**旧版教材文字版**做过逐字比对。比对结果与两处处理：
